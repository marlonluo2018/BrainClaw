Background: Why Can an AI IDE Do All This?

Understanding what makes this possible

💻

An AI IDE is not just a chatbot

Modern AI IDEs (like Claude Code, Cursor) give the AI three superpowers that a regular chatbot doesn't have:

📂

Read & Write Files

The AI can open, edit, and create files on your computer — just like you would in Explorer or Finder.

⌨️

Run Commands

It can execute programs — run Python scripts, call Outlook, open Excel — anything you could type in a terminal.

🧠

Follow Instructions

It reads your instruction files at startup and follows them like an employee following an SOP. No coding needed — just write what you want in plain text.

Result: File access + command execution + instruction following = an AI that can do real work on your machine, not just chat.

Background: What is a "Skill"?

How BrainClaw connects to external tools

🧩

Skills = plug-in connectors

A skill is a small, self-contained module that lets the AI talk to one external system. Think of it like installing an app on your phone.

📧

outlook-skill

Searches your inbox, reads email threads, composes replies, and forwards messages — all through your local Outlook.

📊

xlsx skill

Creates, reads, and edits Excel spreadsheets. Useful for reports, data extraction, and formatting tables.

➕

Add your own

Need to connect to another system? Create a new skill folder with a description file — the AI learns to use it immediately.

Key idea: Skills only do I/O (input/output). They don't make decisions — that's the workflow's job. This keeps things simple and modular.

How It Works

From startup to execution — the full operational flow

1

Startup

Say "start" → AI loads brain files (identity, rules, memory, task queue) and shows your full task dashboard

2

You Speak

Give any command in natural language — "check email", "create task for X", "what do I owe?"

3

Workflow Activates

The AI matches your intent to the right workflow and follows it step by step like an SOP

Example: "Check today emails"

1
EMAIL_WORKFLOW loaded → sets filter to today's inbox
2
outlook-skill called → fetches today's emails, presents summary list

4
User approval → AI asks "Create a task for PMP renewal?" → you confirm
5
TASK_WORKFLOW triggered → creates task with extracted deadline, keywords & asks
6
STAKEHOLDER_WORKFLOW → matches "Ashish" to registry, assigns RACI roles
✓
Task created → AI suggests next steps: "Reply to Ashish to confirm?" or "Check policy for PMP renewal process?"

2-Layer Architecture

A clean separation: Workflows think, Skills act

Layer 1

Workflows

The Brain

All business logic lives here as plain text. The AI reads these like an SOP and follows them step by step.

Task lifecycle Email rules Stakeholder matching Views & reports Event recording
💡 Written in markdown — anyone can read, edit, or add new procedures without coding
calls only when external I/O is needed
Layer 2

Skills

The Hands

Plug-in connectors that talk to external systems. They do I/O only — no business decisions.

Outlook (email) Excel (spreadsheets) Skill Creator (meta)
🔌 Self-contained & reusable — add a new skill without touching workflows
Why this matters: Business rules stay in readable text files, not buried in code. Change a process? Just edit the workflow file.
